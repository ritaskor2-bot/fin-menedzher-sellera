# Фин менеджер селлера

Набор для ведения финансов селлера: правила, скрипты и шаблоны. Работает без данных конкретного клиента — данные кладутся в `input/`, результаты выходят в `output/`.

## Когда применять

- «Сделай план на месяц», «что дозаказать», «наложи остатки».
- «Сколько денег придёт», «где кассовый разрыв», «ДДС».
- «Отчёт за вчера», «как выполняется план по заказам».
- «Разбери неделю», «что с WB», «группы артикулов».
- Новый селлер: с нуля до плана и календаря.

## Структура

```
ФИН менеджер селлера/
├── SKILL.md            этот файл
├── README.md           краткое описание и структура агентов
├── GUIDE.md       пошаговый запуск
├── rules/              01-weekly.md, 02-daily-ozon.md, 03-formulas.md
├── scripts/            make-templates, make-orders-plan, build-cashflow, ozon-daily-digest, lib/xlsx
├── templates/          plan-wb.xlsx, plan-ozon.xlsx
├── input/              данные селлера
└── output/             результаты
```

Агенты системы лежат в `.opencode/agents/`:

| Файл | Режим | Задача |
|---|---|---|
| `fin-menedzher-sellera.md` | primary | маршрутизация и итог |
| `ozon-daily.md` | subagent | дневной отчёт |
| `wb-weekly.md` | subagent | недельный разбор |
| `cashflow.md` | subagent | деньги и ДДС |
| `plan-month.md` | subagent | план на месяц |

## Порядок работы

### 1. Данные

| Что | Файл |
|---|---|
| Выгрузка WB по товарам | `export_report_product*.xlsx` |
| Продажи Ozon | `продажи и выручка*.xlsx` |
| Заказы и % выкупа Ozon | `заказы и % выкупа*.xlsx` |
| Остатки | `остатки.xlsx` |
| Дневной отчёт Ozon | `optiflou-rnp-*.xlsx` |

Перед расчётом проверить: сумма продаж по артикулам = итог отчёта. Расхождение больше 1% — искать причину, не усреднять.

### 2. План на месяц

```
node scripts/make-templates.js
```

Появятся пустые планы. Заполняются столбцы: A артикул, B название, C остатки, E продано за период, F цена до СПП, M % выкупа (дробью). Остальные — формулы.

Флаг «Товара хватит (1/0)»: 1 — категория дошивается, план не режется остатком; 0 — продаём только остаток.

Параметры на листе «Параметры»: дней в периоде факта, дней в первом и плановом месяце, коэффициент роста.

Формулы: прогноз = продажи ÷ дни периода × дни месяца; план месяца = прогноз × рост; план = min(прогноз, остаток − (прогноз − продано)) для флага 0.

### 3. Деньги

```
node scripts/build-cashflow.js --oz-sales 16000000 --wb-sales 4000000 \
  --oz-rate 0.52 --wb-rate 0.35 --purchase 3000000 --opening 0 --out output/cashflow.xlsx
```

- `--oz-rate`, `--wb-rate` — доли выплат (к перечислению ÷ выручка).
- Лаги: Ozon +1 неделя, WB +5 недель (константы `OZ_LAG`, `WB_LAG` в скрипте).
- `--nov-oz`, `--nov-wb` — продажи прошлого месяца, чтобы учесть лаги.
- `--purchase-week` — в какую неделю платить закупку.
- Прочие расходы (ФОТ, налоги, ФФ, реклама) скрипт не считает — добавлять вручную.

Разрыв — неделя, где остаток уходит в минус после обязательных платежей.

### 4. Дневной отчёт

План в заказах: CSV «название;план в заказах в день» →

```
node scripts/make-orders-plan.js --csv input/plan-orders.csv --out input/plan-orders.json
node scripts/ozon-daily-digest.js --file input/optiflou-rnp-2026-12-01-2026-12-01.xlsx --plan input/plan-orders.json
```

Показывает: заказы против плана, топ-17, СПП и скидку, ДРР, показы, CTR, корзину, корзина→заказ, 1–2 действия. Деньги не показывает.

Отправка в Telegram — `--send` и `TG_TOKEN`, `TG_CHAT`. Из РФ нужен VPN.

### 5. Неделя

Порядок: сверка недели → динамика 4 недели → группы → остатки → P&L → касса → отчёт. Детали в `rules/01-weekly.md`.

## Ключевые формулы

```
Выручка до СПП — основная база
Маржинальная прибыль = выручка − себестоимость − комиссия − логистика − хранение − эквайринг − реклама − прочие
Чистая прибыль = маржинальная − постоянные
Маржинальность = марж. прибыль ÷ выручка до СПП
ДРР = реклама ÷ выручка до СПП
Выкуп = выкупы ÷ заказы
Покрытие, дней = (площадка + ФФ + в пути) ÷ скорость за 7 дней
```

Остатки — только из кабинетов или API площадок. Отрицательный остаток = 0, с пометкой.

## Группы артикулов

1. Двигатели — растут, прибыльные.
2. Прибыльные, но падают — маржа плюс, заказы −10%.
3. Минус из-за рекламы — ДРР выше маржинальности.
4. Минус из-за логистики / выкупа.
5. Неликвид — оборот больше 90 дней или продаж нет.
6. Нет остатка.
7. Архив.

## Границы

- Данные клиента (суммы, артикулы, маржа) не выгружать в сторонние сервисы и нейросети.
- Исходники не менять; файлы не удалять и не перемещать без подтверждения.
- Налоги и налоговый режим — зона бухгалтера, не выдумывать ставки.
- Нет данных — спросить, а не подставлять.
- Отчёты наружу не публиковать без разрешения.

## Частые ошибки

1. Сумма по артикулам не равна итогу отчёта — скрытые строки или фильтр.
2. План больше остатка, а товар не придёт — план невыполним.
3. Смешаны периоды: продажи за 19 дней, воронка за 50 — указывать явно.
4. Доля выплат взята «по памяти» — у разных селлеров она разная.
5. Забыты постоянные расходы — маржа без них не прибыль.

## Расширение

Новый субагент: файл в `.opencode/agents/<имя>.md` с frontmatter `description`, `mode: subagent`, `permissions` (удаление и перемещение — `effect: ask`), затем строка в таблице «Кого звать» главного и, если нужно, файл в `rules/`. Перезапустить OpenCode.

Новый селлер: копия папки, свои данные в `input/`, свои доли выплат и лаги, свои категории дошива.
