# 02. Дневной отчёт по Ozon

## Зачем

Один раз в день видеть: выполняем ли план по заказам, где провалилась воронка, что делать сегодня. Без простыней — 10–15 строк.

## Источник

- Факт: дневная выгрузка Ozon (`optiflou-rnp-<дата>-<дата>.xlsx` или аналог), лист «По товарам», только строки уровня «Артикул» (они уже агрегат по размерам).
- План: план продаж на месяц, столбец «План в заказах, шт/день».
- Если в плане формулы без кэшированных значений — выгрузить значения в json перед расчётом.

## Структура сообщения

1. **Дата и выполнение плана:** «Заказы: 310 из плана 516/день — 60,1%».
2. **Топ-17 артикулов** по продажам за день.
3. По каждому:
   - заказы и % выполнения плана в заказах;
   - СПП % и скидка продавца %;
   - ДРР %;
   - показы, CTR, конверсия в корзину, конверсия корзина → заказ;
   - «Делать:» 1–2 действия.

## Что не показываем

- Деньги: выручку, расходы на рекламу, цены в рублях. Только проценты и штуки.
- Отмены и возвраты — в одежде это норма, использовать как контекст, не как рекомендацию.

## Пороги для рекомендаций

| Показатель | Порог | Действие |
|---|---|---|
| Выполнение плана | < 50% | мало заказов: трафик или цена |
| Выполнение плана | > 150% | спрос выше плана: проверить остаток |
| ДРР | > 15% | снизить ставки по слабым запросам |
| ДРР | < 5% и есть рекламные заказы | можно поднять ставки |
| CTR | < 5% | фото и цена в выдаче |
| В корзину | < 3% | цена выше ожиданий |
| Корзина → заказ | < 12% | цена и срок доставки |
| СПП | < 20% | проверить скидку продавца |

## Отправка

Бот в Telegram, токен и чат — в переменных окружения `TG_TOKEN`, `TG_CHAT`. Работает только при доступном `api.telegram.org` (из РФ — через VPN). Id сообщений сохранять, чтобы можно было удалить в течение 48 часов.

## Ограничения

- План месячный, факт дневной — сравнение условное, помечать.
- Один день не тренд: смотреть 3–7 дней подряд.
- Если структура выгрузки поменялась, парсер читает по номерам колонок — проверить перед запуском.
